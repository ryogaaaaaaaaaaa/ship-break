# 0001: 人間向け情報は日本語で運用する

## 状態

採用

## 日付

2026-07-04

## 背景

SHIP//BREAK の人間のゲームディレクターは、英語を快適には読めない。
このプロジェクトでは、ゲームディレクターが仕様、進捗、リスク、失敗、意思決定を自分で確認できることが重要である。

一方で、ソースコード上の識別子や外部 API は英語で扱うほうが、一般的なツール、ライブラリ、開発慣習との相性がよい。

## 決定

人間向けのコミュニケーションとドキュメントは日本語で書く。
プログラム上の識別子は英語のままにする。

具体的には、以下を日本語で書く。

- 進捗報告
- 計画
- 説明
- 質問
- 警告
- 最終要約
- `AGENTS.md`
- `README.md`
- `docs/` 以下の文書
- 意思決定記録
- 失敗記録
- プロジェクト固有の意図を説明するコードコメント

以下は英語のまま扱う。

- class name
- function name
- variable name
- signal name
- file name
- directory name
- data key
- サードパーティのエラーメッセージ
- コマンド出力

サードパーティのエラーメッセージやコマンド出力を人間に伝える場合、原文を無理に翻訳せず、意味と対応方針を日本語で説明する。

## 影響

- 将来の Codex セッションは、人間への返答を日本語で行う。
- 人間向け文書を追加・更新するときは、日本語で書く。
- 技術英語を使う場合は、日本語の説明を添える。
- コードの識別子は英語を維持し、開発ツールとの互換性を保つ。

## 理由

この方針により、ゲームディレクターは英語文書を読まなくてもプロジェクトを理解し、判断できる。
同時に、コードベースは一般的な開発環境と整合した形を保てる。
