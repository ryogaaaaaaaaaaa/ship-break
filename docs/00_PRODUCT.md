# 00 PRODUCT

## フック

**Every time you fix a bug, the game breaks into a different game.**

プレイヤーは発売直前のゲームをテストしている。最初は普通のトップダウンアクションとして始まり、一定時間後にシステム障害が起きる。プレイヤーは各バグに対して `FIX`、`WORKAROUND`、`EXPLOIT` のいずれかを選び、その選択が現在のランのルールを恒久的に変える。

## 目標体験

ランの流れは次を目指す。

```text
NORMAL GAME
-> SMALL ERROR
-> STRANGE INTERACTION
-> BROKEN BUILD
-> PLAYER-OWNED CHAOS
-> FINAL TEST
```

最終的にプレイヤーが「この壊れたゲームは自分が作った」と感じることが核である。

## 商品としての強み

- 短い動画で「何かがおかしい」「プレイヤーが利用している」「ルールが変わった」と伝わる。
- 大量コンテンツではなく、少数のシステムが組み合わさる面白さでリプレイ性を作る。
- デバッグ、エラー、壊れた UI という見た目をゲームメカニクスに直結させる。

## 非交渉の原則

- 最初の60から90秒は、普通で読みやすいゲームとして成立させる。
- バグは単なる悪い状態ではなく、利点・コスト・違う遊び方を持つ選択肢にする。
- コンテンツ量ではなく、ルールの組み合わせで広げる。
- 壊れて見えるが、ソフトウェア自体は bounded、testable、recoverable にする。
